# Скилл: мультипостинг из одного сообщения

## Что владелец получает

Он пишет тебе в чат заготовку — мысль, ссылку на статью или ролик. Дальше:

1. Ты готовишь **один основной пост** и показываешь его на согласование.
2. После «да» ты сам раскладываешь его по площадкам: у каждой свои лимиты, разметка и форматы картинок.
3. Отчитываешься списком ссылок на опубликованное.

Реальный прогон, на который это опирается: один анонс вебинара разошёлся по **девяти
поверхностям в пяти сетях** (Telegram, MAX, страница/лента/группа Facebook, Threads, Instagram,
истории FB и IG) — с четырьмя вариантами картинки: 16:9, 4:5 и два вертикальных 9:16.

---

## 0. Правила, которые нельзя нарушать

- **Публикация только после явного «да» владельца.** Никогда не постишь наружу «на всякий случай».
- **Первый прогон — dry-run.** Показываешь план: какие сети, какой текст, какие картинки, где что урезано.
- **Тестовый канал прежде прода**, если он есть.
- **Секреты — только по имени** (`$MPR_TELEGRAM_BOT_TOKEN`), значения не печатаешь ни в чат, ни в логи.
- **Ссылки не подменяешь** и не навешиваешь свои UTM на чужие партнёрские ссылки.
- **Ошибка публикации — это ошибка**, а не «наверное, ушло»: проверяешь ответ площадки и говоришь честно.

## 1. Что нужно от владельца (по одной площадке за раз)

Спрашивай по мере надобности, не вываливай всё сразу. Токены — через `/secrets`.

| Площадка | Что просить | Имя секрета | Где взять |
|---|---|---|---|
| Telegram | токен бота + id канала, бот — админ канала | `MPR_TELEGRAM_BOT_TOKEN` | @BotFather |
| MAX | токен бота + id канала | `MPR_MAX_BOT_TOKEN` | dev.max.ru |
| Facebook (страница) | долгоживущий Page access token | `MPR_FACEBOOK_PAGE_TOKEN` | Meta app + Graph API, права `pages_manage_posts`, `pages_read_engagement` |
| Instagram | `igUserId` + long-lived token (аккаунт Business/Creator, привязан к странице FB) | `MPR_INSTAGRAM` | тот же Meta app |
| Threads | токен приложения Threads | `MPR_THREADS` | Meta app (Threads API) |
| LinkedIn | OAuth-приложение, refresh-токен, scope `w_member_social` | `MPR_LINKEDIN_OAUTH` | LinkedIn Developers |
| YouTube / RuTube | OAuth или API-ключ | `MPR_YOUTUBE_OAUTH`, `MPR_RUTUBE` | консоли площадок |

Особенности, о которых нужно предупредить владельца заранее:

- **Instagram не публикует текст без картинки** и берёт медиа **только по публичному URL** —
  локальный файл не подойдёт, картинка сначала должна лечь на доступный в интернете адрес.
- **Ссылка в подписи Instagram некликабельна** — CTA веди в шапку профиля.
- **Telegram Bot API не умеет Stories.** Истории — только через отдельный аккаунт-юзербот,
  это отдельное решение владельца, по умолчанию не включаем.
- **Facebook: постим от имени страницы**, не от личного профиля — постинг в личный профиль через API закрыт.
- **MAX**: адрес API `botapi.max.ru`, токен передаётся заголовком `Authorization`, для запросов
  из РФ может понадобиться российский корневой сертификат.
- **Автозеркало TG→MAX** (если у владельца включено) срабатывает только на посты человека,
  посты бота не зеркалятся — публикуй в обе сети явно.

## 2. Как устроен контент

Одна папка на один пост — это точка правды:

```
content/<slug>/
  manifest.json      # что за пост, куда ушёл, ссылки на опубликованное
  telegram.md        # основной текст (markdown), из него делаются остальные
  facebook.txt       # версия plain-text, если нужна
  threads.txt        # версия ≤500 знаков
  images/
    01-gorizont-16x9.png    # для лент: Telegram, Facebook, MAX
    02-vertikal-4x5.jpg     # Instagram
    03-story-ig-9x16.jpg    # история Instagram
    04-story-fb-9x16.jpg    # история Facebook
```

Правила:

- **Порядок картинок держится именами файлов** (`01-`, `02-`…). Переименование ломает порядок в карусели.
- **Форматы**: 16:9 — ленты, 4:5 — Instagram, 9:16 — истории, 1:1 — карусели.
- **Подпись под фото в Telegram — 1024 знака.** Длиннее — отправляешь двумя сообщениями:
  фото, следом текст.
- **Threads — 500 знаков.** Не обрезай на полуслове: переписывай короче.

## 3. Стиль владельца

Заведи файл `style.md` рядом со скиллом и держи его актуальным. Минимум, что там должно быть:

- как обращаться к аудитории (на «ты» / на «вы»);
- допустимы ли эмодзи и в каком количестве;
- чем заканчивается пост (CTA, ссылка, подпись);
- запретные слова и темы;
- чем отличается тон в разных сетях (в Telegram длиннее и спокойнее, в Threads короче и злее).

Каждый раз, когда владелец правит твой текст, — дописывай правку в `style.md`. Через десяток
постов согласования почти прекращаются.

## 4. Конфиг связки

Связка = «откуда берём» + «куда раскладываем». Шаблон — `pipeline.example.json` рядом с этим файлом.
Копируешь, подставляешь свои id каналов, имена секретов держишь как в таблице выше.

## 5. Порядок работы

```
1. Владелец кидает заготовку («анонс вебинара 2 сентября, ссылка …»).
2. Ты пишешь основной пост по style.md и готовишь картинки нужных форматов.
3. DRY-RUN: показываешь пакет — тексты по сетям, картинки, что куда, где урезано по лимиту.
4. Владелец правит и говорит «публикуй».
5. Публикуешь по порядку: основной канал → остальные ленты → истории.
6. Проверяешь каждую публикацию: сохраняешь ссылку/идентификатор в manifest.json.
7. Отчитываешься списком ссылок. Если где-то не ушло — говоришь прямо, а не «должно было».
```

### Проверка вместо доверия

- **Порядок карточек в карусели** сверяй перцептивным хешем: скачай опубликованные картинки
  обратно и сравни с исходниками. Именно так ловится «карусель уехала задом наперёд».
- **Длину подписи** проверяй до отправки, а не по ошибке площадки.
- **Ссылки** открывай — не публикуй битые.

## 6. Что делать нельзя

- Публиковать в личный профиль Facebook через API (закрыто правилами площадки).
- Включать юзербот Telegram на личном аккаунте владельца ради историй — это против правил
  Telegram и риск блокировки. Только отдельный аккаунт и только по явному решению владельца.
- Массово рассылать одинаковый текст в чужие группы — это спам, площадки за это банят.
- Публиковать чужие фотографии и тексты без прав на них.

## 7. Как понять, что скилл настроен

- [ ] Есть `style.md` с тоном владельца.
- [ ] Заведён и проверен `healthCheck` хотя бы одной площадки (бот отвечает, канал доступен).
- [ ] Прошёл dry-run на тестовом посте и владелец согласовал результат.
- [ ] В `manifest.json` первого поста есть ссылки на все площадки, куда он ушёл.
